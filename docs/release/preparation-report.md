# 部署方案还有哪些缺口

## 现有容器只覆盖原 Gradio

Dockerfile 的入口是完成权重/环境预检后启动 clickvos.web_app；没有复制统一网站静态文件，也没有为统一网站网关准备容器运行配置。现有 Docker 方案不能直接当作作品站和真实工作台的一体化云部署。

当前基础镜像使用标签，SAM2 提交和主要依赖有固定版本，但系统包、构建工具及部分传递依赖尚未完全锁定。不能仅凭 Dockerfile 写出“可复现构建已成功”，需真实构建后记录镜像 ID、digest 和实际依赖。

## 下一步验收顺序

1. 在有 Docker 与 NVIDIA 容器支持的独立环境，先验证 Docker/Compose 版本和配置。
2. 使用独立检出和空输出目录构建，核对权重挂载与容器内 CUDA、FFmpeg。
3. 使用已有授权 T1 短片跑上传、整车选择、传播和实际 ZIP 核验，再用 T3 验证多对象与中间帧修正。
4. 保存构建日志、镜像信息、应用提交、任务编号、耗时、显存和下载校验结果；核查重启后的文件持久化。
5. 统一网站容器化和云端受控 HTTPS 访问另行验收，记录实际费用和边界。

当前 gpus 属性需 Compose 2.30.0 或更新版本，依据 Docker 官方服务属性文档。静态 YAML 解析不能替代 docker compose config，也不能代替 GPU 容器运行。

详细命令、验收字段和官方文档链接已放入 deployment-readiness.md。本轮没有购买算力、安装 Docker 或修改账号配置。
