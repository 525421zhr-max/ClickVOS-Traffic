# ClickVOS Traffic 软件使用说明书

审阅稿 / 2026-10-10 / 应用包版本 0.1.0

## 1. 软件用途与适用范围

ClickVOS Traffic 用于交通视频的交互分割和半自动标注。操作者上传视频，在画面上为指定目标添加提示点，由 SAM2 生成后续帧的掩码，再人工检查、修正并导出。软件支持车辆、行人、非机动车三类标签，目标身份和类别由操作者指定。

一个目标对应一个对象 ID。同一辆车上可以添加多个正点，不需要为每个点新建目标。两名行人需要两个目标；背景车辆即使在画面里出现，也不会因为出现就自动成为本次标注对象。

本说明书对应应用提交 60f72860f1968d3ce714d728eead90bac7dc2a3a。当前有原 Gradio 应用和统一网站工作台两个入口；核心分割与导出能力共用，部分界面功能不同。正式十人试用沿用原 Gradio 和固定任务卡。

| 入口 | 主要用途 | 当前边界 |
| --- | --- | --- |
| 原 Gradio 应用 | 正式试用、标注、首帧和中间帧修正、历史查看和回收区恢复 | 默认 200 MiB / 300 帧；单活动推理会话 |
| 统一网站工作台 | 项目介绍和真实标注一体化；本机或授权临时 HTTPS 访问 | 最多 30 秒 / 100 MiB / 2000 处理帧，并检查对象数与资源预算 |

模型可能漏选细结构、把相似目标跟混，或在遮挡与快速运动时失去目标。生成了文件不等于标注正确，需人工复核。30 秒是有条件的输入上限，尚无任意场景持续跟踪稳定的保证。

# 2. 运行与打开网站

## 已有本机环境

当前验证环境为 Windows 上的 Ubuntu-24.04 WSL、Python 3.12.3、PyTorch 2.11.0+cu128、SAM2.1 Hiera Tiny、Gradio 6.27.0。需要 FFmpeg/FFprobe、可用的 NVIDIA GPU 和匹配的模型权重。参与者在主持人的电脑上使用浏览器，无需自行安装开发环境。

正式试用使用已准备的本机桌面“ClickVOS 试用启动”入口。主持人先选 H 预检，正式参加者使用 P01-P10。此快捷方式属于当前电脑的操作辅助，源码安装到新电脑时需按部署文档重新配置，不应将快捷方式单独发给其他电脑当作安装包。

| 本机地址 | 打开方式 |
| --- | --- |
| http://127.0.0.1:7867 | 主持人按固定试用配置启动后的 Gradio |
| http://127.0.0.1:7860 | README 默认启动的 Gradio，和试用端口不同 |
| http://127.0.0.1:7882/ | 统一网站连接页，仅在 GPU 主机上打开 |
| http://127.0.0.1:7880/#workbench | 已启动的本机统一工作台 |

## 统一网站入口

在仓库根目录 PowerShell 执行以下现有命令之一：

```powershell
./scripts/start_unified_site.ps1 -LocalOnly -Open
./scripts/start_unified_site.ps1 -Open
```

第一条只使用本机；第二条启用临时 HTTPS 访问。停止该服务使用 `./scripts/start_unified_site.ps1 -Stop`。它不替代前台 Gradio 的停止操作。

手机或其他电脑不能通过自身的 127.0.0.1 访问主持人电脑。远程体验需主持人当天提供有效 HTTPS 地址和访问码；电脑及服务保持运行，每次仅一人操作。临时地址可能变化。不要同时运行两套 GPU 任务。

# 3. 上传、点选和传播

## 准备视频

使用自有、明确授权或许可清楚的视频。正式试用使用指定的 T1、T2、T3 文件。原 Gradio 上传后点击“抽帧并显示首帧”，待画面出现再创建目标。统一工作台按页面步骤先上传并选择处理帧率。

## 创建目标与添加点

1. 选择“目标类别”，点击“新建目标”。
2. 确认“当前目标”的 ID。选择“正点”，在目标内部点击。整车可在不同部位补充提示，避免只选到车门。
3. 选择“负点”可排除误选背景，负点不要落在希望保留的细小结构上。
4. 需要另一名行人或另一辆车时，再新建第二个目标。为同一目标补点时继续使用原 ID。
5. 如果重复创建了目标，在“当前目标”选中多余 ID，点击“删除当前目标”，再核对剩余提示。

每个目标至少需要一个正点。类别是标注标签，不代表模型自动识别了该类别。“两个目标”表示创建了两个 ID，不是系统自动检测到两辆车。

## 运行并复核

原 Gradio 点击“3. 运行 SAM2 传播”；统一网站点击对应的视频分割操作。等待运行结束后检查首帧分割和完整预览，至少查看开头、中间、末尾以及遮挡、目标接近或离场的位置。

重点检查对象是否完整、是否换成其他人或车辆、是否含有背景和相邻目标。未完成传播、发生失败或提示尚未应用时，不把旧预览当作本次有效结果；按页面错误提示处理。

# 4. 首帧与中间帧修正

## 首帧预览与重新传播

初次传播完成后，可在首帧结果区选择要补点的目标。添加正点或负点后，点击“仅更新首帧预览”，观察局部效果；“撤销最后一个补点”可移除最近的补点，再次预览确认。

只有首帧预览不会更新整个视频的正式标注。决定采用当前提示后，点击“用补点重新传播”。存在未应用的提示或选项时，当前任务导出会要求先完成重新传播。

负点不一定使分割变好。已完成的自行车诊断中，负点虽减少部分误覆盖，也增加了细结构漏分，因此用户应对比真实效果，而不是默认每次补点都有效。

## 中间帧修正

1. 在“修正帧号（从 0 开始）”输入帧号并点击“载入修正帧”。
2. 选择正确的目标 ID 和修正点击类型，为该目标添加提示。
3. 点击“应用修正并重新传播”，等待从该帧向后更新。
4. 复核修正帧及其后续结果，确认没有引入新的误选。

第 15 帧是界面中的零基索引 15，不是把第一帧记为 1。统一网站中，在应用或撤销当前修正提示后再切换目标或帧，避免留下未处理提示。

## 异常提醒的用途

原 Gradio 支持异常帧定位、重新激活候选确认及撤销。提醒用于帮助人工复核，不等于已确认目标正确重现。当前尚缺连续空掩码后同一真实目标重现的充分素材，不能据现有普通遮挡片段估计该规则在所有交通场景的效果。

# 5. 下载、保存和历史任务

## 实际下载标注 ZIP

完成复核后，点击“生成标注下载包”，再点击生成的 ZIP 文件实际下载。单独保存预览视频只能用于观看，不能代替完整标注包。换视频或关闭页面前先确认 ZIP 已保存。

| 文件 | 内容 |
| --- | --- |
| project.json | 视频规格、对象 ID、类别、提示、异常及修正记录 |
| annotations/coco_rle.json | COCO 结构的未压缩 RLE 标注 |
| preview.mp4 | 各对象彩色叠加预览 |
| masks/object_NNN/*.png | 每个对象的逐帧二值掩码；前景 255、背景 0 |
| first_frame_review.json | 使用首帧复核的新任务中的动作记录 |

下载包不包含原始上传视频和抽帧目录。原视频与结果的使用仍遵守各自来源许可。没有前景的对象帧仍可保存空 PNG；COCO 图像记录保留，但该空对象帧不创建 annotation。

正式试用时，由主持人将 ZIP 原文件名保存在 `downloads/Pxx/Tn/`。重试使用不同子目录，保留之前的文件、编号和耗时。已有下载核验工具依赖原文件名与本机任务对应，不要任意加前缀。

## 历史与恢复

原 Gradio 可只读打开本地历史任务、查看结果并重新导出；任务可经预览和编号确认移入可恢复回收区，再从回收区恢复。回收区恢复是文件恢复，不是恢复可继续编辑的 SAM2 内存会话。

统一网站目前没有历史恢复入口，服务重启后需要重新上传；磁盘上保存的任务输出不会因此自动成为可编辑会话。永久过期清理尚未实现，回收区不会自动释放磁盘空间。不要手工删除正式试用的 sessions 目录。

# 6. 限制与常见问题

| 现象 | 如何处理 |
| --- | --- |
| 本机网页打不开 | 确认启动窗口仍运行、所用端口与入口一致；保留报错，不连续启动多个服务 |
| 手机打不开 localhost | 使用主持人当天提供的临时 HTTPS 地址；本机地址不能跨电脑使用 |
| 5 秒视频超过帧数上限 | 时长和帧数不同，高帧率会快速达到上限；正式试用直接用准备好的固定素材 |
| 同一辆车有两个 ID | 删除多余目标，在保留的 ID 下继续添加多个提示点 |
| 补点后结果变差 | 复核负点是否伤及细结构，必要时撤销；重新传播后再检查 |
| 点过“生成”但找不到结果 | 还需点击生成的 ZIP 下载；在浏览器下载列表核对文件 |
| 传播失败或资源不足 | 保存错误信息，按提示减少处理帧或目标；失败结果不得当作成功导出 |

统一网站限制为最多 30 秒、100 MiB、2000 处理帧，还检查目标数×帧数不超过 2000、像素数不超过 4096×2160，以及实时内存和磁盘。例如两目标、30 秒、60 FPS 约有 3600 个目标帧，需要选择 30/15 FPS 或减少任务规模。

降低处理帧率可能漏掉快速变化。全部帧模式不自动复制帧；可变帧率源的预览按平均 FPS 播放，当前不保留原始逐帧时间戳。原 Gradio 的固定试用配置仍为 200 MiB/300 帧，不自动继承统一网站的 30 秒配置。

遇到问题时记录任务编号、入口、帧数、对象数、错误文字和已做的操作。试用记录的耗时、帮助次数和评分须现场记录，不能从 ZIP 事后推测。

# 7. 技术组成与验证范围

## 主要组件

界面层由 Gradio 与统一网站 HTML/CSS/JavaScript 构成；统一网站通过有访问码的 FastAPI 网关复用标注回调。视频预处理使用 FFmpeg，推理调用固定版本的 SAM2.1 Hiera Tiny，导出模块生成 PNG、JSON、COCO RLE 和预览视频。

| 模块 | 项目内职责 |
| --- | --- |
| video_io.py / task_store.py | 抽帧、任务目录、历史与回收 |
| sam2_engine.py / lazy_frames.py | 提示管理、传播封装、按需帧读取 |
| first_frame_review.py / anomaly.py | 首帧动作记录与异常分析 |
| export.py | 标注与预览导出 |
| web_app.py / site_api.py | 原界面回调与统一网站网关 |
| web/site/ | 网站介绍和标注工作台界面 |

SAM2 模型、PyTorch、Gradio、FastAPI、FFmpeg 及第三方字体图标均为外部组件。项目材料描述的是本仓库的集成、交互、任务管理、异常复核和导出实现，不将上游模型或第三方素材写为本项目原创。

## 已有证据与尚待完成

已有短视频、多目标、修正和 ZIP 对照的工程记录。DEV-37 保存过 536 帧双目标流程与 1072 张 PNG/RLE 一致性检查，但后段镜头被遮住，产生 832 张空掩码；该结果只证明工程流程，不能证明持续跟踪准确。
