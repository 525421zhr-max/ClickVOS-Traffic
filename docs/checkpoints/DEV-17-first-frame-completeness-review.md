# DEV-17：首帧对象完整性复核

- 日期：2026-09-21
- 状态：产品引导与回归测试完成

## 背景

DEV-16 的 `car-roundabout` 对照显示：一个正点落在车门时，SAM2 可以稳定传播车门局部，而不是整辆车。传播本身看似稳定，但对象粒度从首帧就已经错误。因此界面不能只让用户查看完整视频，还需要把首帧结果单独放到决策位置。

## 完成内容

- 传播结果区并列展示“首帧分割检查”和“完整传播预览”。
- 首帧检查紧邻可操作说明，不使用阻断流程的弹窗。
- 任一目标只有一个正点时，明确列出目标 ID，并提醒车辆或非机动车可能只选中车门、车窗或车轮。
- 提示用户返回第 2 步，在目标不同部位补充正点；负点只放在不需要的邻近物体上。
- 已有多个正点时仍要求人工检查完整实例和邻近物体，避免把点数误当成质量保证。
- 标记步骤的常驻说明同步改为车头、车身和车尾等具体位置，减少抽象术语。

该提示不声称能自动识别“完整目标”。当前判断只使用正点数量，实际质量仍由用户查看首帧叠加结果确认。

## 实际验证

- 单元测试覆盖单正点警告、多正点提醒和 Web 回调的七项输出。
- `python -m pytest -q`：`45 passed`
- `python -m compileall -q src tests scripts`：通过
- `python scripts/check_repository.py`：通过
- Impeccable 界面机械检查：无发现项
- 临时启动 `http://127.0.0.1:7862`：HTTP 200，页面标题包含 `ClickVOS Traffic`；验证后已关闭临时服务

## SAM2 原生扩展诊断

当前环境能够使用 PyTorch CUDA 12.8 运行推理，但 `nvcc` 不存在，因此 SAM2 安装时没有生成可选 `sam2._C` 扩展。结果是运行时跳过孔洞填充后处理；核心提示分割和视频传播仍可工作。

修复需要安装完整 CUDA Toolkit 并重新编译 SAM2，属于较大的系统环境变更。本轮没有为了消除可选警告而修改系统；后续应在独立检查点完成安装、扩展导入验证和 DEV-16 同条件复测。
