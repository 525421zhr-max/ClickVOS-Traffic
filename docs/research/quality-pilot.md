# 掩码清晰度与串目标诊断试验

## 冻结合同（2026-09-17）

- 问题：最大连通区域过滤能否减少 SAM2 掩码覆盖到其他、不相连目标的现象，同时保留被点击主体？
- 基线：SAM2.1 Hiera Tiny 原始二值掩码，现有提示和传播设置不变。
- 对照：同一视频、同一权重、同一提示，唯一变化为逐帧只保留最大连通区域。
- 数据：先使用已登记的公开交通样本 `traffic-001`；用户网页上传且来源不明确的视频不进入研究证据。
- 预算：一次 50 帧基线复用已有 CP-02 结果；新增一次 50 帧过滤运行，单 GPU，不新增模型、数据集或随机种子。
- 端点：记录每帧连通区域数、过滤前后像素数、删除像素比例，并人工检查首帧、面积变化峰值帧和第 46 帧。
- 通过条件：至少一个多连通区域帧的非主体区域被删除，且被点击主体在人工检查帧仍保留；若所有帧本来只有一个连通区域，则结果记为“不适用/信息不足”，不能宣称改进。
- 结论边界：该过滤只能处理不相连的误覆盖；目标与错误区域连成一片、边界本身不准或身份漂移仍需要负点、中间帧修正或更大模型。

缺失指标统一写 `TBD (pending)`；没有逐帧真值时不报告 IoU、J、F 或精度提升。

## 重新激活保护误拦截试验合同（2026-09-23，运行前）

- 问题：道路交通序列里，SAM2 在短暂输出空掩码后恢复同一对象时，现有连续空 3 帧保护是否会把正确掩码拦下？
- 输入：DAVIS 2017 `crossing` 道路片段，对象 ID 1（首帧右侧深色衣服行人）；初始正点 `(370,300)`、`(365,270)`、`(375,355)`，负点 `(285,285)`。第三个正点在运行前由 `(384,364)` 调整，因为首帧真值显示原坐标落在背景；四个最终点已核对标签。筛选时只看 RGB 帧和真值，不根据模型输出选择帧。若完整序列不满足道路交通场景或首帧对象清晰可点的条件，记为筛选不通过，不把其他片段结果替代本次结果。
- 比较：同一组 SAM2.1 Hiera Tiny 原始逐帧掩码与阈值 3 的重新激活保护结果；首帧正负点和全部帧固定，不启用最大连通区域过滤。
- 预算：仅一条完整序列的一次单 GPU 推理；不训练、不重复种子、不追加模型配置对比。
- 主端点：原始掩码从连续至少 3 帧空白后重新非空的触发事件数；每个事件帧的原始掩码与同一实例真值的 IoU。IoU ≥ 0.5 且真值可见的触发事件记为“正确对象被拦”，IoU < 0.5 或真值不可见的事件只记为待人工复核，不自动宣称身份漂移。
- 判定：若有至少一个满足 IoU ≥ 0.5 的触发事件，则确认该规则存在本序列的误拦截案例；若没有任何触发事件，则本次对“误拦截”问题为信息不足；若有触发事件但无正确对象被拦，仅能说本序列未观察到误拦截。不得从一条序列估计总体误拦截率。
- 控制：先核对 RGB 帧、真值、预测掩码帧名与尺寸一一对应；首帧 IoU 须达到 0.7，否则视为提示工程失败，不解释保护规则。模型权重使用现有 SAM2.1 Hiera Tiny 固定文件。缺失结果记 `TBD (pending)`。

## DAVIS crossing 三目标联合传播试验合同（2026-09-24，运行前）

- 问题：现有 ClickVOS/SAM2 多目标会话能否在同一道路画面中一次传播两名行人和一辆货车，并为三个对象分别输出完整的 52 帧掩码？这是功能与小样本质量验证，不是 DAVIS 全集基准。
- 输入：已登记且完整下载的 DAVIS 2017 `crossing` 480p 52 帧及对象 1、2、3 的逐帧真值。对象 1 使用 DEV-20 原提示；对象 2（左侧浅色衣服行人）正点 `(285,285),(300,315),(315,355)`，负点 `(370,300)`；对象 3（左侧货车）正点 `(50,300),(150,300),(190,330)`，负点 `(285,285)`。这些点在运行前已用首帧真值核对正负标签。
- 协议：同一 SAM2.1 Hiera Tiny 权重，按 ID 1、2、3 依次在第 0 帧添加提示，然后一次向前传播完整序列；不启用最大连通区域过滤、重新激活保护或中途修正。只跑一遍，不依据结果追加提示。
- 预算：一条 52 帧序列、一次单 GPU 三目标推理；复用现有官方 DAVIS 评价环境，不下载新数据或训练模型。
- 主端点：三个对象各自完整保存 52 张二值掩码，帧名与真值一致；各对象首帧 IoU 须 ≥0.7，未达门槛则该对象归为提示失败，不解释其后续 J/F。通过门槛的对象用官方 DAVIS 实现计算中间 50 帧 J、F、J&F，分别报告，不把三个对象汇成总体性能。
- 诊断：记录联合推理时间、峰值 CUDA 分配和保存帧数；对象 1 与 DEV-20 相同提示的单目标结果仅作同序列观察性对照，不用单次差异宣称多目标优劣。任何输出 ID、掩码尺寸或帧数不符，记为工程失败，先修复再评价。
- 结论边界：此序列只有行人和机动车，不覆盖道路非机动车；三目标同场景仍不是跨视频泛化或误拦截率证据。缺失结果记 `TBD (pending)`。

- 门槛与主端点：每对象保存 80 张同尺寸二值掩码，帧名一一对应；每对象首帧 IoU ≥0.7 才接受其后续质量端点。按现有 DAVIS J/F 函数逐对象评估中间 78 帧；首帧失败者的后续分数仅作为提示失败诊断，不合并为已通过成绩。

- 结论边界：一条自行车道序列不构成城市道路非机动车基准、总体精度或保护规则总体误报率；缺失结果为 `TBD (pending)`。原始帧、GT、掩码与预览留在本地。
