# ClickVOS 十人试用 v1

状态：准备中，真实参与者 0 人。DEV-32 是开发者浏览器回归，不计入十人试用。

## 目的与固定条件

观察新用户能否独立完成交通目标标注、复核和下载，收集操作困难。不是分割精度基准，也不与其他软件比较效率。

- 计划 10 位参与者，编号 P01–P10，不记录姓名、手机号、账号或人像。
- 在同一台已验证的 Windows/WSL/CUDA 机器上逐人进行，本地服务只监听 127.0.0.1；不声称并发多用户已验证。
- 应用基线 `b971298d375866191359425005e4dd4db57fea49`，SAM2.1 Hiera Tiny；默认后处理保持开启。准备工具/文档的后续提交不算应用版本变化。若修改 Web 或推理行为，先记录新版本并重做相关回归，不把不同版本的记录直接合并。
- 所有人按 T1→T2→T3 顺序。逐级教学会带来学习效应，因此不能用三项时间比较类别难度或推断因果。
- 预计每人 35–45 分钟（安排建议，不是实测）：介绍/练习约 5 分钟，三项上限合计 30 分钟，问卷和反馈约 5 分钟。
- 本轮只准备材料，不自动招募、联系参与者或启动十轮 GPU 测试。

## 主持人操作

1. 核对试用包中的 `assets.json`、视频规格、应用版本、权重和 GPU；确认没有其他模型任务占用。同一套视频用于所有人。
2. 说明“我们测试的是软件是否好用，不是考你；可随时停止。记录匿名操作时间、结果和反馈，不录音、不录屏、不收集账号信息”。对方愿意参加后再开始，拒绝/退出如实记录。
3. 讲解上传、正点/负点、传播和下载。可用程序的空界面说明，练习不使用正式任务答案。正式任务只给下面的目标描述，不给点击坐标或演示完成路径。
4. 每项从参与者读完任务并开始操作计时，到 ZIP 实际下载且主持人核对必要产物时停止。包含模型等待；中断和等待可在备注中解释，不事后随意扣除。超时仍保留已有产物，转下一项；不为提高成功率重新记一次。
5. 如有求助，可重复任务原文；操作提示、指出按钮/点击位置、代操作均算帮助，写入 `help_notes`。发生帮助后即使完成，也只能记 `assisted`。不主动替参与者修正失败结果。
6. 每项新建任务，在记录中填写软件任务编号；需要重试时保留之前的任务编号与耗时，不能覆盖第一次失败。每项最多 3 次完整传播、2 次单帧预览、1 次中间帧传播；达到时间或次数上限即停止。发生崩溃等环境问题记 `failed` 并写原因，后续版本复测另开记录。
7. 下载包可用 `scripts/verify_downloaded_bundle.py` 核对。该脚本用于主持人核验，不是给参与者额外布置的任务。
8. 按参与者本人回答记录各项易用程度 1–5（1 很难，5 很容易）、整体满意度 1–5，以及最困惑的步骤/最希望改进的一点。未回答写 null，不代填中间分。

每位参与者使用各自配置的任务目录；换人时先停止服务，再使用下一编号的配置启动。不要让后一位沿用前一位的浏览器任务/活动会话或参考其答案。这是同机顺序试用的操作隔离，不是经过安全验证的多租户服务。

## 参与者任务卡

### T1：标一辆车（上限 8 分钟）

打开 `T1-car.mp4`，选择首帧中央、车头朝右的深灰色小汽车。请尽量覆盖整辆车，而不是只选车门；完成传播，检查开头、中间和末尾，并下载标注包。

必要完成项：创建车辆目标；产生完整 75 帧输出；人工首帧复核能识别指定整车，不能只有明显局部车门或换成背景车；实际下载可打开的 ZIP。主持人的人工复核记录为可用性验收，不写成 IoU 成绩。视频来自 DAVIS car-roundabout，10 FPS 为本地回放设置，不代表原始采样时间。

### T2：分别标两名行人（上限 10 分钟）

打开 `T2-pedestrians.mp4`，分别标记首帧中间背对镜头的白发浅色上衣行人，以及其右侧深蓝色上衣行人。请给两人建立不同目标，检查传播结果并下载标注包。

必要完成项：两个行人目标、每对象完整 50 帧、首帧人工核对两人身份分开、实际下载 ZIP。只标指定两人，不处理画面内其他路人。

### T3：复核和修正两名骑行者（上限 12 分钟）

打开 `T3-riders.mp4`，分别标记前方近处和远处两名骑行者的人体，自行车本体不在本题目标范围。完成首次传播后，在首帧尝试补一个背景负点并只更新首帧预览；检查变化，撤销该点，再更新预览并重新传播。载入第 15 帧，为选中的目标添加一个修正点并应用，最后下载标注包。

必要完成项：两个非机动车类别的人体目标、每对象完整 30 帧、补点/预览/撤销/再次传播日志存在、一个第 15 帧修正记录、实际下载 ZIP。操作演示完成不等于质量改善；若修正反而变差，在反馈中记录，不要求凑出“提升”。

## 填写规则与预先约定的统计

运行准备脚本后，`records/P01.json` 至 `P10.json` 全为空白待测记录。只修改真实发生的记录；原始记录留本地，不提交 Git。`participated` 只有真实开始试用才设 true。

每项 `outcome`：`pending` 未开始、`independent` 无操作帮助且所有必要项完成、`assisted` 有帮助且完成、`failed` 已尝试但未完成、`timeout` 达到上限、`skipped` 未尝试。只有 independent/assisted 的 `acceptance_passed` 为 true。`elapsed_seconds` 是实际秒数；超时只说明到上限时未完成，不把该时间当成成功耗时。`input_clicks` 记录全部正负点点击尝试，撤销不减；`correction_actions` 记录点击“应用修正并重新传播”的次数；`help_count` 和备注一致。无法可靠计数时写 null 并注明，不能填 0。

- 每项独立完成率 = independent 人数 / 实际尝试人数。实际尝试为 independent、assisted、failed、timeout；pending/skipped 不进入分母，另报人数。
- assisted 单列，不混为独立完成。可另报总完成数 independent+assisted。
- 仅对已完成任务报告完成时间中位数，附样本数；失败/超时单列，不忽略，也不填为 0 秒。
- 点击、修正和满意度使用非空真实记录，附有效样本数；不填补缺失值，不做显著性或总体推广。
- 10 位参与者均真实参加且每项结果有明确记录后，才可说“十人试用完成”。退出/跳过允许发生，应披露缺失，不能补造数据。
- 首轮改进触发条件：任一任务实际尝试者的独立完成率低于 80%，或至少 3 人在同一步遇到相同阻碍，就优先修复该问题。未满 10 人的结果只是阶段反馈；不能改门槛来接受结果。

试用文件仅本地非商业教学/研究使用，来源和条款见 `assets.json` 与 [素材登记](../research/data-sources.md)。不把 DAVIS 帧、媒体、掩码或个人反馈上传公共仓库/Sites；公开作品页仅使用另行准备并核验的说明与允许公开的展示内容。
