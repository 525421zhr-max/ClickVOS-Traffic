# ClickVOS Traffic 路线图

## 当前基线

- CP-00：项目目录和重建规则已建立。
- CP-00B：WSL 24.04、Python 3.12、PyTorch 2.11+cu128 和 RTX 5060 CUDA 已验证。
- CP-01：Meta SAM2.1 Hiera Tiny 已安装，合成视频的正负点分割、传播和 PNG 保存已验证。
- CP-02：已使用 CC BY 3.0 夜间高速公路视频完成 50 帧传播，记录了目标驶出后错误重识别另一车辆的失败案例。
- CP-03：统一会话已支持多对象提示、逐对象传播和指定对象中间帧修正。
- CP-04：本地 Web 已完成上传、多个目标正负点、彩色预览、指定对象修正和结果下载闭环。
- CP-05：逐对象 PNG、合成视频、项目 JSON 和 COCO RLE 已统一打包，并接入 Web 下载。
- CP-06 子任务：重新激活检测、保护、异常定位、候选确认及撤销已在 CP-02 失败案例上验证；多对象重叠规则已实现，更多真实正例与误报评估仍待补充。
- 本地任务可以只读打开、预览和重新导出；尚未恢复可编辑的 SAM2 会话，也没有任务删除功能。
- Dockerfile、Compose、GPU/权重预检和部署文档已加入；当前机器没有 Docker，镜像构建与云 GPU 运行尚未验证。
- 历史任务支持占用预览、任务编号二次确认、移入可恢复回收区及 Web 恢复；尚未提供永久过期清理。
- 行人和非机动车授权短视频均已完成真实 GPU 回归；DAVIS 自行车序列已跑通官方 J/F 指标链路，但该序列不是道路交通场景。
- DAVIS 验证集 `car-roundabout` 已完成道路车辆真值试验，确认提示点只覆盖局部时会稳定传播错误的对象粒度，多点覆盖整车可显著改善该序列。
- DAVIS `crossing` 已完成一条道路行人真值验证；模型 52 帧持续输出非空掩码，因此重新激活保护误拦截问题在该序列上信息不足。
- Web 结果页已增加首帧掩码完整性复核；单正点目标会得到具体补点引导。
- 首帧结果区已支持直接补正负点、撤销最后一点并复用同一任务重新传播。

## 阶段一：交通视频核心闭环

对应 CP-02 至 CP-05。

- 选择一小段合规交通视频，建立数据来源记录。
- 将验证脚本重构为可复用的视频预处理和 SAM2 推理模块。
- 支持目标类别、对象 ID、多目标和中间帧追加提示。
- 建立 Gradio 上传、点击、传播、预览与下载闭环。
- 导出二值掩码、叠加视频和标准标注。

这一阶段完成后，新用户应当能根据说明完成目标选择、修正和导出，项目也能在新环境中重新搭建。

## 阶段二：失败检测与性能证据

对应 CP-06 至 CP-07。

- 建立不加后处理的 SAM2 基线。
- 实现面积、质心、IoU、消失和重叠等异常信号。
- 在固定视频上比较单点、正负点、框和中间帧修正。
- 比较模型规模、分辨率与 offload 配置。
- 在带真值的公开子集上计算 J、F、J&F，并记录 FPS、端到端时间和显存。

这一阶段需要回答三个问题：哪些场景有效、哪些场景容易失败、异常提醒是否真的对用户有帮助。

## 阶段三：用户试用与产品完善

对应 CP-08。

- 固定三类难度递增的交通标注任务。
- 邀请十名用户，每人完成相同任务。
- 匿名记录成功率、完成时间、点击次数、修正次数、错误和满意度。
- 根据高频问题改进交互、错误提示和用户手册。

这一阶段结束时，应当保留完整的十人试用原始记录，并能复核统计方法和结论。

## 阶段四：部署与结题

对应 CP-09 至 CP-10。

- 固定依赖，构建容器并验证云 GPU 部署。
- 增加任务队列、文件限制、隔离目录和过期清理。
- 冻结软件版本，整理软著源代码和说明书。
- 完成结题报告、部署文档、用户手册、演示视频和答辩 PPT。

结题前，本地和云端至少各保留一次可复现运行记录，软著与结题材料使用同一个冻结版本。

## 最近三项工作

1. 扩展到带逐帧真值的道路非机动车，并冻结统一的提示协议。
2. 寻找确有连续空掩码和同一目标重现的交通片段，评价保护规则的误拦截。
3. 确定回收区永久清理的保留期策略和审计要求；在此之前不自动删除。
